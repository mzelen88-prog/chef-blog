# chef-blog — личный сайт на Тильде со своим кодом

Персональный сайт-визитка, блог, продажа услуг и продуктов, предоплата за
мастер-классы и гастро-ужины. Платформа — Tilda. Дизайн и интерактив — свой
код из этого репозитория.

## Разделение ответственности

Тильда закрывает то, что дорого и рискованно писать самим:

| Задача | Чем закрыто |
|---|---|
| Блог: админка, поля поста, автогенерация страниц | CMS «Потоки» (до 5000 записей, любой тариф) |
| Приём предоплат, эквайринг, чеки по 54-ФЗ | Блок «Корзина» ST100 + ЮKassa |
| Заявки | Формы Тильды |
| Хостинг, SSL, CDN картинок, sitemap | Тильда |

Мы пишем то, чего у Тильды нет:

- Дизайн — Zero Block + наш CSS-бандл, чтобы сайт не выглядел шаблонным
- Лайки и комментарии — своё, у платформы их нет
- Шеринг постов
- Логика блога: теги, оглавление, время чтения, связанные посты

## Жёсткие ограничения платформы

Проверено по документации Тильды. На этом стоит вся архитектура:

1. **API Тильды только на чтение.** Запушить код в страницу программно нельзя.
   Всё, что попадает в редактор, вставляется руками — поэтому в Тильде живёт
   минимум: разметка и одна строка подключения бандла.
2. **Тильда не хостит свои .js/.css.** Бандл раздаётся снаружи, через jsDelivr
   прямо из этого репозитория.
3. **Свой код не работает в превью редактора**, только после публикации.
   Поэтому есть `preview/` — локальный эмулятор окружения.
4. **ЮKassa работает только с блоком «Корзина» (ST100).** Свой чекаут делать
   нельзя: на других блоках оплата выдаёт ошибку. Все продажи идут через корзину.
5. **PHP не поддерживается.** Любая серверная логика — только снаружи.

## Правила кода

Тильда грузит на каждую страницу свой CSS и jQuery. Наш код обязан быть
изолирован, иначе он сломает платформу или платформа сломает его.

- **Префикс `cb-` на всём.** Классы `.cb-*`, переменные `--cb-*`,
  атрибуты `data-cb-*`. Без исключений.
- **Никаких голых тегов и `*` в селекторах.** `.cb-card p` — нормально,
  `p {}` или `* { box-sizing }` — нет.
- **Не цепляться к классам Тильды.** `.t-*`, `.tn-*`, `.t396__*`, `#rec…`
  меняются без предупреждения. Нужен якорь — вешаем свой класс через
  настройки блока (CSS class) и цепляемся к нему.
- **Не полагаться на недокументированные функции Тильды** (`t_onReady`,
  `t_onFuncLoad`). Только `DOMContentLoaded`, `MutationObserver` и
  документированные события вроде `tildaform:aftersuccess`.
- **В глобальную область — ничего**, кроме namespace `window.CB`.
- **jQuery на странице есть, но мы им не пользуемся** — чтобы не зависеть от
  версии, которую Тильда может сменить.

## Инициализация

Тильда рендерит блоки лениво, поэтому компоненты не могут просто отработать на
`DOMContentLoaded`. Точка входа — `src/js/index.js`: монтирует фичи по
data-атрибутам и дальше следит за DOM через `MutationObserver`. Каждый
компонент обязан быть идемпотентным — смонтированный узел помечается и
второй раз не монтируется.

## Сборка и деплой

    npm install       # один раз
    npm run build     # src/ → build/site.min.js + build/site.min.css
    npm run watch     # пересборка на лету, для работы с preview/
    npm run preview   # локальный сервер на http://localhost:4321

`build/` **коммитится в репозиторий** — это не ошибка. jsDelivr раздаёт файлы
прямо из GitHub, несобранного бандла CDN не увидит.

Релиз:

    npm run build
    git add -A && git commit -m "…"
    git tag v1.2 && git push --tags

## Подключение в Тильде

Настройки сайта → Ещё → HTML-код в head:

    <link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/mzelen88-prog/chef-blog@v0.1/build/site.min.css">
    <script defer src="https://cdn.jsdelivr.net/gh/mzelen88-prog/chef-blog@v0.1/build/site.min.js"></script>

Репозиторий: https://github.com/mzelen88-prog/chef-blog (публичный — jsDelivr
раздаёт только открытые).

Версия в URL зафиксирована тегом. Откат при поломке — поменять цифру и
опубликовать: одна правка, без деплоя.

**Тег никогда не перезаписывается.** jsDelivr кеширует содержимое тега надолго,
поэтому `git tag -f` даст расхождение между репозиторием и тем, что реально
отдаётся браузеру. Каждый релиз — новый тег.

Разметка компонентов лежит в `blocks/` — по файлу на блок T123 или HTML-элемент
Zero Block. Меняешь разметку в репозитории, копируешь в Тильду. Логика и стили
при этом не трогаются, они приезжают из бандла.

## Структура

    src/js/lib/        хелперы: монтирование, DOM
    src/js/features/   компоненты
    src/css/           tokens.css — дизайн-токены, components/ — стили
    blocks/            HTML-снипеты для вставки в Тильду
    build/             собранный бандл (коммитится!)
    preview/           локальный эмулятор окружения Тильды
    assets/            SVG-иконки и прочее, что попадает в бандл

## Правовые решения по проекту

Прошли юридическую проверку в сентябре 2026. Решения ниже приняты сознательно —
не меняй их, не сверившись с Максимом.

**Алкоголь.** Страница продаёт ужин, а не сидр. Не возвращать описания
производителей, сортов и вкусовых достоинств: реклама алкоголя в интернете
запрещена (п. 8 ч. 2 ст. 21 ФЗ-38), и характеристики напитков — главный
признак такой квалификации. Подробный рассказ о сидре живёт офлайн:
бумажное меню в зале, стена сидра, слова ведущей. На странице обязательны
18+ и предупреждение о вреде.

**Возврат предоплаты.** Полный возврат при обращении до начала ужина.
Безусловное удержание ничтожно по ст. 32 ЗоЗПП. Формулировку не ужесточать.

**Аллергии.** В форме и переписке не спрашиваем — это данные о здоровье
(ст. 10 ФЗ-152). Гостю предлагаем позвонить и сказать голосом; нигде
не фиксируем. Не заводить поле «аллергии» в формах и таблицах.

**Телеграм.** Только общие вопросы. Данные для брони там не собираем —
вопрос локализации по ч. 5 ст. 18 ФЗ-152. Кнопки записи в телеграм не ведут.

**Доступ к спискам гостей** — только у ИП. Ни имён, ни ролей сотрудников
в политике.

**Реквизиты.** На странице — место оказания услуг (Усиевича, 18), а не адрес
из ЕГРИП: он совпадает с местом жительства. Обязательны ОГРНИП, ИНН
и сведения о зарегистрировавшем органе (ст. 9 ЗоЗПП).

**Политика обработки данных** обязательна с момента, когда сайт начнёт
собирать данные через интернет — то есть при появлении формы записи
(ч. 2 ст. 18.1 ФЗ-152). Пока запись только по телефону, триггер не наступил.

**Уведомление в РКН** подано на ИП Кудюков М.А. ранее. При добавлении
новых целей и способов обработки нужно сообщение об изменениях, не новое
уведомление (ст. 22 ФЗ-152).
